# Адаптер: Claude Code — журнал расхода и одобрения

Читайте этот файл, только если текущий клиент — Claude Code (CLI, IDE, web или Desktop) и
нужен [расход для итога](runtime.md#расход-для-итога) или факт одобрений для
`approvals.observed`. Запуск child и транспорт — в [runtime.md](runtime.md) и, для Desktop, в
[его адаптере](runtime-claude-code-desktop.md). Поля ниже наблюдались в Claude Code 2.1.325;
формат журнала меняется быстрее скила, поэтому сверяйте его в текущей версии.

## Журнал

Транскрипт сессии — JSONL в каталоге проектов Claude Code
(`~/.claude/projects/<cwd с заменой разделителей на дефисы>/<session_id>.jsonl`).
Транскрипты субагентов клиент хранит отдельно от parent; найдите их рядом с транскриптом
parent по ID сессии и проверьте, что строки относятся к нужному child.

## Запросы и токены

- Ответ модели — запись `type: "assistant"`. Один ответ записывается несколькими строками
  (по блокам) с одним `message.id`: запрос — уникальный `message.id`, не число строк.
- Расход — `message.usage` любой строки ответа (у строк одного `message.id` он одинаков): `input_tokens` (вход без кэша),
  `cache_creation_input_tokens` (запись в кэш), `cache_read_input_tokens` (чтение из кэша),
  `output_tokens`. Вход без кэша в итоге — `input_tokens + cache_creation_input_tokens`;
  чтение из кэша — отдельно.

## Одобрения

- Решение о вызове инструмента — поле `permissionDecision` у записи результата вызова:
  `decision` (`accept` и другие), `source`, `reasonType` (`classifier` — автоматический
  классификатор режима auto, `rule` — правило настроек, `mode` — режим разрешений).
  Ответ человека виден по `source` (наблюдалось `user_temporary`); у части решений
  конфигурации `reasonType` нет.
- Решение пишется в транскрипт той сессии, которая вызывала инструмент: привязка к child
  и через control к назначению точная.
- Расход классификатора в транскрипт не пишется. В итоге: число решений по `reasonType` и
  `decision`, «токены недоступны». Не оценивайте их по числу решений.
