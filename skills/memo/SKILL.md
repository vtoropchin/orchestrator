# Протокол работы с памятью проекта

Проект хранит долговременную память в MCP-сервере `memo` (инструменты
`memory_recall`/`memory_save`/`memory_update`/`memory_forget`, конфиг — `agentmemory.toml`
в корне репозитория). Имя проекта в памяти — значение `[scope] project` этого файла; ниже
оно обозначено `<имя>`. Прочитайте его из файла, а не из названия каталога. Файла нет —
scope неизвестен: не пишите в память, пока пользователь его не подтвердит (скил `adapt`
создаёт файл при подключении памяти).

## Когда вызывать

- **В начале любой задачи** — `memory_recall` с описанием задачи. `scope`/`scopes`
  не указывай: инстанс сам подставит домашнее пространство `project:<имя>`
  плюс общий слой `user:*` (см. `agentmemory.toml [scope]`). Так
  подтягиваются решения, договорённости и прогресс прошлых сессий.
- **По ходу и в конце задачи** — фиксируй новое через `memory_save`: один
  атомарный факт (1–3 предложения) за вызов. `scope` в схеме инструмента
  обязателен (без `omitempty`) — передавай пустую строку `scope:""`,
  если хочешь дефолт `project:<имя>`, а не опускай ключ. Явно
  `scope:"project:<имя>"` — для проектных фактов/решений/граблей; явно
  `scope:"user:*"` — для общих привычек и предпочтений пользователя, не
  привязанных к этому проекту.
- **Известный техдолг** — тем же `memory_save` с `kind: debt`: что не
  так + где + почему отложено + критерий закрытия. Долг сам не затухает — закрывай
  явно через `memory_forget(id, replaced_by=…)`.
- **Факт изменился** — `memory_update` (id записи + только изменённые поля).
- **Факт устарел или ошибочен** — `memory_forget` (мягкое удаление; можно
  указать `replaced_by`, если факт заменён более новым).

## Ambient-режим (хуки)

Если клиент агента настроен с хуками memo (например, начала сессии и отправки промпта) —
recall уже выполнен автоматически ДО того, как ты увидел промпт: ищи в начале контекста блок `## Долговременная память проекта (авто-recall)`.
В этом случае вызывай `memory_recall` вручную только для точечных уточняющих
запросов, которых не покрыл автоматический бриф (напр. по узкой формулировке,
не совпавшей с фиксированным запросом хука). Если такого блока нет — хуки не
настроены или клиент их не поддерживает — делай recall вручную в начале задачи, как
описано выше.

## Правила scope

- `memory_save` без явного scope пишет в `project:<имя>` — домашнее
  пространство этого инстанса.
- `memory_recall` без scope/scopes ищет в `project:<имя>` + `user:*`.
- Явный scope/scopes в вызове всегда перекрывает дефолт инстанса.

## Если сервер недоступен

Если инструменты `memory_*` не видны в сессии — агентское приложение не
подняло MCP-сервер `memo` (сервер не сконфигурирован или не одобрен
приложением, бинарь `memo` недоступен) или reasoner/embedder работают в
деградированном режиме (пустой
`DEEPSEEK_API_KEY` — проверь `.env` рядом с `agentmemory.toml`, memo
подхватывает его сам при старте). Продолжай задачу без долговременной памяти,
предупредив об этом.
