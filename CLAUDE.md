# Skills

## Архитектура

Это репозиторий переносимых Agent Skills, создаваемых с помощью Claude Code, а не приложение
и не собственный установщик. Дисциплина разработки — набор `.claude/skills/`, точка входа `/dev`.
Спецификация формата: https://agentskills.io/specification.

### Соответствия понятий

| Понятие | Реализация здесь |
|---|---|
| Компонент | Самодостаточный пакет скила: отдельный непосредственный подкаталог `skills/` |
| Порт | Текстовый контракт входов, результата и условий применения; программных интерфейсов нет |
| DTO | Формат SKILL.md с YAML frontmatter и включённые ресурсы; программных DTO нет |
| Сущность | Метаданные и предметные правила в инструкциях скила; модель приложения не создаётся |
| Main | Внешний skills CLI и агент-потребитель; собственной composition root нет |
| Видимость | `skills/` — распространяемое, `.claude/` — среда авторинга; источник установки выбирается явно |
| Подмена в тестах | Временный пакет и отдельный временный проект-потребитель без глобальных установок |
| Проверка зависимостей | Формат — skills-ref; ссылки и скрытые предпосылки — ревью; перенос файлов — smoke test |
| Анализ графа | Граф импортов отсутствует; не вводить искусственные слои и линтер импортов |
| Время и случайность | Детерминированные фикстуры; порты часов/генераторов нужны только при появлении такой логики |

### Идиомы этого формата — не нарушения

Для декларативных Markdown/YAML-пакетов отсутствие ООП-интерфейсов, DI, доменных слоёв
и собственной Main не является нарушением. Оценивать автономность пакета и контракт
инструкций, а не требовать каркас исполняемого приложения.

### Структура и границы

- `skills/`: плоский публичный каталог. Один каталог — один скил с обязательным SKILL.md.
  `scripts/`, `references/`, `assets/` внутри скила опциональны.
- `.claude/skills/` и `.claude/agents/`: служебные инструменты разработки. Не переделывать
  общие скилы под этот проект; проектные стабильные правила живут здесь.
- Набор «Чистая архитектура» (`adapt`, `dev`, скилы дисциплины) публикуется из `skills/`;
  правки делать там. `.claude/skills/` — служебная копия для этого репозитория, обновляется
  установкой из `skills/` и `adapt`, а не ручным копированием.
  Роли агентов набора — нейтральные файлы `skills/dev/references/agents/`. Скилы `memo` и
  `memo-bootstrap` в набор не входят: их ставит `memo init` проекта agent-memory.
- `templates/skill/SKILL.md.template`: шаблон, не устанавливаемый скил. Не переименовывать
  его в SKILL.md внутри шаблонов и не распространять недописанные шаблоны как готовые скилы.
- `scripts/check-skills.sh`: тонкая оболочка официального валидатора, не реализация спецификации.
  Проверка принимает каталог пакетов аргументом и не исполняет содержимое проверяемых скилов.
- Публичный пакет не зависит от среды авторинга: её CLAUDE.md, настройки memo, служебных
  агентов, соседних скилов или авторских абсолютных путей. Все обязательные локальные ресурсы
  находятся внутри пакета. Отдельно настроенный пользователем MCP, включая memo, допустим
  как явно объявленная внешняя зависимость конкретного пакета; скил сам его не устанавливает.
- Пути ресурсов задаются относительно корня скила, а не текущего каталога потребителя.
  Запрещены обязательные ссылки и симлинки за границу пакета.
- Не завязывать переносимый скил на названия инструментов одного клиента без необходимости.
  Необходимые CLI, runtimes, MCP, сеть и ограничения клиента объявлять явно. Их установка
  и выдача доступов не являются частью обычного копирования скила.
- Скил должен работать в разных клиентах (Claude Code, DeepSeek Harness, Hermes и др.).
  Основной сценарий описывает нужные возможности, а не инструменты; имена инструментов
  клиента — только в отдельном адаптере `references/runtime-<клиент>.md`. Нет нужной
  возможности — явный блокер или объявленный альтернативный транспорт, не скрытая подмена.
- Для публикации и установки использовать именно подкаталог `skills/`. Из корня CLI также
  обнаружит служебную `.claude/skills/`: разделение каталогов само по себе их не скрывает.

### Контракт скила

- `name` уникально, совпадает с именем каталога, имеет 1–64 символа; использовать `a-z`,
  `0-9`, `-`, без крайних и двойных дефисов.
- `description` — непустая строка не длиннее 1024 символов: назначение и конкретные триггеры.
  Дополнительные поля — по спецификации. Не делать необязательные поля обязательными.
- Инструкции содержат проверяемые входы/результат, процедуру, примеры и обработку ошибок.
  Рекомендации по длине тела не превращать в ограничения формата.
- Перед распространением проверить обычный запрос, пограничный случай и отсутствие зависимости.
  Валидация метаданных и установка не заменяют такую поведенческую проверку.
- Не включать секреты. Разрешения на публикацию, удаление, перезапись, установку глобально
  и другие внешние эффекты получать отдельно. Лицензию самовольно не назначать.

### Команды проверки

Из корня проекта:

- Метаданные публичных пакетов: `sh scripts/check-skills.sh`.
- Синтаксис оболочки: `sh -n scripts/check-skills.sh`.
- Контракт ревью: `sh .claude/skills/dev/scripts/review-lint.sh`.

Проверка метаданных требует uv/uvx при наличии пакетов; исходник skills-ref закреплён
коммитом в скрипте. Загрузка идёт в кэш uv, `.env` не подхватывается. Библиотека
демонстрационная: она не гарантирует корректность ссылок, безопасность или качество скила.
Пустой каталог обязан сообщать 0 скилов — это не доказательство проверки реальных скилов.

Локальный smoke test выполняется стандартным skills CLI в отдельном проекте-потребителе
с фиксацией версии CLI, без `-g`; проверяются SKILL.md и ресурсы. Удалённую установку
проверять после появления реального remote. Проверка клиента не доказывает работу всех агентов.
Локальные структурные проверки не требуют БД/UI/сети, ориентир — до 10 секунд; загрузка
внешнего валидатора и install smoke в этот ориентир не входят. Тестов ядра приложения нет.

### Изменяемые детали и память

Установщик, клиент агента и инструменты проверки остаются внешними деталями. Публичный пакет
должен переноситься отдельно от среды авторинга. Не добавлять приложение, инфраструктуру
или собственный установщик без отдельной задачи.

Решения, компромиссы и контекст — в memo проекта Skills, а не в этом файле. Протокол —
`.claude/skills/memo/SKILL.md`; recall в начале задачи, запись по ходу. Стабильные правила —
здесь; контракт риска и гигиена ревью — в REVIEW.md. Наличие файлов конфигурации не доказывает,
что текущая сессия подключена к правильному scope: проверить его до сохранения памяти.
