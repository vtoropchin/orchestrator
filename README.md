# Skills

Репозиторий для создания переносимых скилов ИИ-агентов с помощью Claude Code.
Формат — [Agent Skills](https://agentskills.io/specification), установка — стандартный
[skills CLI](https://github.com/vercel-labs/skills), который используется на skills.sh.
Собственного установщика здесь нет.

## Публичные скилы

| Скил | Назначение | Внешние требования |
|---|---|---|
| [orchestrate](skills/orchestrate/SKILL.md) | Тонкий parent: реальные child-сессии или субагенты, делегированный dev-цикл, независимая проверка и восстановление v3 | Клиент агента, запускающий child со свежим контекстом (сессии или субагенты); настроенный MCP memo с подтверждённым project scope |
| [session-worker](skills/session-worker/SKILL.md) | Scout/planner/dev-lead/worker/verifier: полные details у потребителей, короткий результат parent | Полный brief v3 и канал к parent (адресуемая связь или итог вызова субагента); без memo нужен независимый verifier с memo и проверяемыми источниками evidence |
| [i-have-adhd](skills/i-have-adhd/SKILL.md) | Стиль сообщений для читателя с СДВГ: первым — следующее действие, нумерованные шаги, без преамбулы. `dev` и `orchestrate` включают его по умолчанию только для сообщений пользователю; выключается фразой «stop adhd mode». Копия [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd) (MIT), отличия — в [upstream.md](skills/i-have-adhd/references/upstream.md) | Нет; без него оркестраторы пишут в обычном стиле |

Универсальны по типу работы (разработка, исследование, документация) и по клиенту агента:
Claude Code, DeepSeek Harness, Hermes Agent и другие клиенты с поддержкой Agent Skills.
Установка скилов не устанавливает MCP и не выдаёт доступы.

## Поддержка разных агентов

Протокол v3 не зависит от клиента. Координатор в начале работы сверяет фактические
инструменты текущего агента с нужными возможностями и выбирает транспорт:

| Транспорт | Что нужно от клиента | Где обычно |
|---|---|---|
| `session` | Долгоживущие child-сессии с адресуемой двусторонней связью и сверкой запусков | Claude Code Desktop |
| `delegated` | Субагенты со свежим контекстом, возвращающие итог parent | DeepSeek Harness, Hermes Agent, Claude Code без инструментов сессий |

При `delegated` ожидание grant заменяют два вызова: gate-вызов возвращает только `ready`,
exec-вызов несёт grant в prompt и возвращает короткий итог. Если клиент даёт оба транспорта,
выбирается `session`. Если ни одного — работа блокируется: CLI других агентов, tmux, SDK-скрипты,
fork беседы и исполнение всех ролей в одном контексте не подменяют child-агентов.
Подробности — [runtime.md](skills/orchestrate/references/runtime.md); имена инструментов
Desktop собраны в отдельном [адаптере](skills/orchestrate/references/runtime-claude-code-desktop.md).

Что проверить в конкретном клиенте:

- скилы видны агенту: установите их стандартным skills CLI с выбором нужного агента
  или скопируйте каталоги из `skills/` туда, где клиент ищет скилы (например,
  `.agents/skills` проекта для DeepSeek Harness);
- MCP memo подключён в настройках клиента и виден не только parent, но и субагентам;
  иначе нужен независимый verifier с memo;
- субагент запускается со свежим контекстом, а не копией беседы parent.
Шаблон в `templates/` не является готовым скилом и не появляется в списке установки.

## Набор «Чистая архитектура»

Цель набора та же, что у книги: **уменьшить человеческие трудозатраты на создание и
сопровождение системы**. Слои, порты и метрики — средства, а не цель. Набор языко-независим
и не привязан к одному кодинг-агенту.

**Установка и адаптация — два шага:**

1. Установить набор в проект — из корня проекта или из корня этого репозитория:
   ```bash
   make -C /путь/к/skills install
   ```
   Первый вопрос — рабочая директория (по умолчанию — каталог, откуда запущен make);
   укажите проект. В диалоге CLI выбрать все скилы набора (`adapt`, `dev`, `clean-architecture`,
   `solid-design`, `component-structure`, `architectural-boundaries`,
   `use-cases-and-entities`, `testable-architecture`, `code-organization`,
   `details-and-deferral`), агентов, которыми пользуетесь
   (например, Claude Code, Hermes Agent, Universal для `.agents/skills` — его читает
   DeepSeek Harness), и проектную область.
2. Открыть проект в своём агенте и запустить скил `adapt` (`/adapt` или «адаптируй набор
   чистой архитектуры под этот проект»). Он изучит стек, покажет план и после согласия:
   создаст именованных агентов из ролей `dev` там, где у клиента есть адаптер (сейчас —
   Claude Code: `.claude/agents/`), подключит память `memo` командой `memo init`, если
   [agent-memory](https://github.com/vtoropchin/agent-memory) установлен (она же ставит скилы
   `memo` и `memo-bootstrap` с именем проекта), запишет стабильные правила в
   `AGENTS.md`/`CLAUDE.md`, создаст каркас `REVIEW.md` и проверку правила зависимостей.

После этого задачи начинаются со скила `dev`. Обновление — снова `make install`
и `adapt` в режиме обновления: файл правил, конфиги и `REVIEW.md` сохраняются; проектные
дополнения в файлах скилов `adapt` найдёт по `git diff` и предложит перенести в файл правил.

**Как набор работает в разных клиентах.** Роли агентов (`architecture-reviewer`,
`implementer` и др.) хранятся нейтральными файлами в `skills/dev/references/agents/`; `dev`
запускает их именованным агентом клиента, общим субагентом с файлом роли или, если
субагентов нет, отдельным проходом в основном контексте. Ревью на баги идёт встроенной
командой клиента или субагентом-ревьюером. Подробности —
[runtime.md](skills/dev/references/runtime.md); имена инструментов Claude Code — в адаптерах
[dev](skills/dev/references/runtime-claude-code.md) и
[adapt](skills/adapt/references/runtime-claude-code.md). Ручной путь адаптации —
[manual-adaptation.md](skills/adapt/references/manual-adaptation.md).

Принципы набора: правило зависимостей не нарушается, остальное — вопрос цены; граница
вводится в точке перегиба, а не «на всякий случай»; детали (БД, веб, фреймворк, ОС)
остаются заменяемыми; тестируемость — следствие границ; для маленькой стабильной системы
честный ответ — «дисциплина избыточна».

## Структура

```text
skills/                         распространяемые скилы: по каталогу на скил
  orchestrate/                  координатор child-агентов и memo-протокол
    SKILL.md                    метаданные и основной сценарий
    references/                 контракты, runtime клиентов, bootstrap и сценарии проверки
  session-worker/               самостоятельный исполнитель
    SKILL.md                    роль, ready/grant, выполнение, ограничения
    references/                 полный контракт назначения и отчёта
  adapt/                        адаптация набора «Чистая архитектура» под проект и клиентов
  dev/                          оркестратор цикла разработки
    references/agents/          нейтральные роли агентов набора
    scripts/                    review-lint и его тест
  clean-architecture/ …         скилы дисциплины
templates/skill/SKILL.md.template  шаблон для авторинга, не готовый скил
scripts/check-skills.sh          проверка метаданных публичного каталога
.agents/skills/                  служебная установка набора (dev, adapt и др.) и memo для DeepSeek Harness
.claude/skills/                  симлинки на .agents/skills/, memo и skill-creator для Claude Code
.claude/agents/                  служебные агенты разработки
CLAUDE.md                       стабильные правила этого проекта
REVIEW.md                       риск изменений и контракт ревью
agentmemory.toml                локальная настройка memo, scope project:Skills
```

`skills/` и `.claude/skills/` имеют разные роли. CLI обнаруживает оба каталога при установке
из корня репозитория. Чтобы получить только распространяемые скилы, передавайте CLI путь
именно к `skills/`. Это соглашение о пути установки, а не механизм скрытия служебных скилов.

## Работа через дочерние сессии

Пример после проектной установки:

```text
/orchestrate economy
Выполни две независимые проверки документации через дочерних агентов.
Не меняй файлы. Верни проверяемые источники и противоречия.
```

В клиентах без slash-команд достаточно попросить агента использовать скил orchestrate.
Координатор ведёт цель, назначения и приёмку в memo; дочерние агенты исследуют,
выполняют работу и независимо проверяют результат. Полные ТЗ и доказательства
читают их потребители, родитель получает короткие сводки со ссылками. Это снижает
накопление контекста родителя, но не обещает меньшего общего расхода без измерений.

- **Режим:** economy — до двух активных контекстов; fast — без числового потолка
  (`active_limit: null`), если пользователь не задал положительный целый cap.
  Все роли и bounded agents входят в общий учёт; idle не освобождает слот.
- **Запуск:** только parent запускает child средствами своего клиента. Intent → bind →
  ready → grant предшествуют работе; отказ клиента не обходится другой ролью или механизмом.
- **Владение:** один writer на физический ресурс, включая алиасы и побочные записи.
  Обычная зависимая работа ждёт явной приёмки; verifier получает отдельный read-grant
  после release writer, чтобы проверить ещё не принятый результат.
- **Приёмка:** verifier сам сверяет все изменения с исходным baseline и повторно
  проверяет закреплённую версию. Parent проверяет независимость, корреляцию и точный
  набор criterion IDs, а не перечитывает весь diff. Изменение после аудита отменяет verdict.
- **Git:** `start-target-linear-delivery/v1` фиксирует стартовую цель и baseline.
  Content pass открывает отдельную последовательную Git-фазу; после локального коммита
  нужен independent final_git pass. Только затем parent открывает downstream.
  Read-only/non-Git/no-change — явно not_applicable, без пустого коммита.
- **Автономность:** обычные решения принимаются без вопросов о каждой стадии;
  после двух неудачных repair пересматривается стратегия. Человек нужен только для
  необходимого физического действия либо доказанного блокера прав/инструментов/scope.
  Push, публикация, worktrees, архивирование и удаление не разрешаются автоматически.
- **Восстановление:** передайте root ID; parent сверит текущий фронт, сохранённые
  лимиты и реальные сессии. Timeout не release; неопределённый запуск/commit сначала
  сверяется, а не повторяется. Ожидание — через поддерживаемые события, без polling.

Каждое сообщение child к parent с envelope, final и wrap-up — до 2000 символов.
Полные brief/result/evidence остаются в отдельных memo details, не в файловом реестре
и не потоком сообщений. Без memo у child evidence получает независимый verifier с memo;
если проверяемого пути нет, назначение блокируется. Parent без memo или без запуска child не начинает работу.

Пакеты самостоятельны: `orchestrate` содержит bootstrap на случай отсутствия
`session-worker`. **Протокол v3 несовместим с v1/v2**; обновляйте обе используемые копии
согласованно. Установка файлов не настраивает MCP и не выдаёт доступов.
Полные схемы и ограничения находятся в пакетах:
[orchestrate](skills/orchestrate/SKILL.md), [session-worker](skills/session-worker/SKILL.md).

## Создать скил

Из корня этого репозитория:

```bash
mkdir -p skills/my-skill
```

```bash
cp templates/skill/SKILL.md.template skills/my-skill/SKILL.md
```

Замените `my-skill` на имя задачи в названии каталога и в `name`. Заполните инструкции,
удалите заметки автору и добавьте только необходимые ресурсы. Альтернативный способ начать —
официальный `npx skills init my-skill` из каталога `skills/`.

Минимальный frontmatter:

```yaml
---
name: my-skill
description: "Конкретная задача скила и ситуации, в которых агенту следует его применять."
---
```

Обязательные правила:

- `name`: 1–64 символа; для совместимости используйте `a-z`, `0-9` и `-`, без дефисов
  по краям и `--`. Имя совпадает с названием каталога и уникально в публичном каталоге.
- `description`: непустая строка до 1024 символов, содержащая назначение и триггеры применения.
  Обязательны только `name` и `description`; дополнительные поля — по спецификации.
- Инструкции описывают входы, ожидаемый результат, конкретную процедуру, примеры и обработку
  ошибок. Не заменяйте процедуру обещанием «сделать хорошо».
- Ресурсы входят в пакет. Пути разрешаются относительно корня скила, а не текущего каталога
  пользователя. Не используйте обязательные ссылки за пределы пакета или симлинки наружу.
- Публичный скил не зависит от среды авторинга: её `.claude/`, `CLAUDE.md`, настройки memo,
  соседних скилов или абсолютных путей автора. Внешние инструменты, MCP и ограничения
  клиента объявляются явно; отдельно настроенный пользователем memo допустим как явная
  зависимость конкретного пакета. Они не устанавливаются автоматически вместе со скилом.
- Не встраивайте секреты и не требуйте загрузить проектную `.env`. Побочные эффекты
  вроде публикации, удаления, перезаписи и глобальной установки требуют разрешения.

Спецификация рекомендует держать `SKILL.md` короче 500 строк и выносить подробности в
`references/`; это рекомендация, а не ограничение формата. Лицензия не выбрана автоматически:
согласуйте права на распространение перед публикацией.

## Проверки

Потребуются `sh` и [uv](https://docs.astral.sh/uv/) с `uvx`. Для установки через CLI нужны
Node.js 22.20+ и npm. Оба инструмента могут загружать пакеты в свои кэши; это не глобальная
установка команд, но записи вне репозитория будут.

Проверить все публичные скилы в плоском каталоге `skills/`:

```bash
sh scripts/check-skills.sh
```

Проверить другой каталог с пакетами, например временные фикстуры:

```bash
sh scripts/check-skills.sh /path/to/skill-catalog
```

Скрипт вызывает официальный `skills-ref validate` через `uvx --no-env-file` и фиксирует
исходник валидатора на коммите `83021e2be457a9b6679148719c1f6074f0ad975e`.
Глобальная установка Python-пакета и собственный YAML-парсер не нужны. Проверка запускается
из каталога нашего скрипта, а не из проверяемого пакета. При ошибке возвращается ненулевой
статус; пустой каталог явно сообщает `0 public skills; nothing to validate`.

`skills-ref` — демонстрационная reference library. Она проверяет метаданные, но не доказывает
безопасность, корректность ссылок, качество инструкций или поведение агента. Дополнительно
нужны установка из локального пути в отдельный тестовый проект, проверка наличия ресурсов и
сценарии выполнения: нормальный запрос, пограничный случай, отсутствие зависимости.
Установка для одного агента не подтверждает совместимость со всеми остальными.

Для v3 сверяйте схемы пакетов/bootstrap, локальные ссылки и автономность.
Установите закреплённым `skills@1.7.6 --copy` в три временных consumer-проекта:
каждый пакет отдельно и оба вместе, без `-g`. Поведенческая матрица (независимая
приёмка, stale version, владение, бюджет, Git-доставка и малый контекст parent) — в
[verification.md](skills/orchestrate/references/verification.md).

Различайте **S** — статическую проверку, **F** — явную фикстуру/симуляцию,
**R** — реальные child-запуски в конкретном клиенте и транспорте (R одного клиента
не доказывает другой). Установка, Git CLI-фикстуры и ответы модели на
сценарии не доказывают R или измеренную экономию. Живой smoke lead + independent
verifier требует отдельного разрешения.

Отдельная проверка контракта ревью:

```bash
sh .claude/skills/dev/scripts/review-lint.sh
```

Она требует Git-репозиторий и учитывает новые неигнорируемые файлы без коммита. Это проверка
гигиены `REVIEW.md`, а не валидатор скилов или линтер зависимостей приложения.

## Интерактивная установка через Make

Из корня этого репозитория:

```bash
make install
```

Или из любого другого каталога, например из корня проекта-потребителя:

```bash
make -C /путь/к/skills install
```

Первый вопрос — «Укажите рабочую директорию»; по умолчанию подставлен каталог, откуда
запущен make (Enter — принять). Можно ввести другой путь: абсолютный, относительный
(от каталога запуска) или с `~`. Несуществующий каталог переспрашивается, Ctrl+D отменяет
установку. Весь дальнейший процесс идёт из выбранной директории: проектная установка
попадает именно в неё. Значение по умолчанию можно задать заранее:
`make install PROJECT=/путь/к/проекту`.

Затем запустится обычный диалог закреплённого `skills@1.7.6`: выберите нужный скил или
несколько, агента, проектную/глобальную область и способ установки, затем подтвердите итог.
Выбор в списке — пробел, переход дальше — Enter; отмена — Ctrl+C.

DeepSeek Harness (dsh) в списке агентов CLI отдельно не показан: этот список зашит в
`skills@1.7.6`, и расширить его извне нельзя. dsh читает `.agents/skills` проекта — это секция
«Universal (.agents/skills)», которую CLI ставит всегда; для dsh нужна проектная область.
`make install` напоминает об этом перед диалогом, а после установки печатает, сколько скилов
источника лежит в `.agents/skills` выбранного проекта, то есть что увидит dsh.
`dev` и `orchestrate` по умолчанию включают стиль `i-have-adhd`, поэтому отметьте его вместе
с ними; если оркестратор установлен, а `i-have-adhd` нет, `make install` напомнит об этом.
Источник — только публичный каталог `skills/` этого репозитория (определяется по
расположению Makefile), без служебных скилов `.claude/skills/`. Диалог и запуск CLI —
в `scripts/install.sh`.

Команда требует интерактивный терминал и не передаёт флаги автоматического выбора или
подтверждения. Маркеры `AI_AGENT`, `CLAUDECODE` и `CLAUDE_CODE` удаляются только из окружения
дочернего CLI, чтобы он не включил автоматические подтверждения из-за окружения Claude.
Без терминала команда прекращает работу до вызова CLI. Node.js/npm и Make нужны отдельно;
Makefile не содержит собственного установщика.

## Установка из локального проекта

Команды выполняются **из корня проекта-потребителя**, не из этого репозитория.
Для воспроизводимости примеры закреплены на `skills@1.7.6`.

Оба готовых пакета для Claude Code, проектная независимая копия:

```bash
DISABLE_TELEMETRY=1 npx --yes skills@1.7.6 add /Users/vladimir/Programming/Skills/skills --skill orchestrate session-worker -a claude-code --copy -y
```

Только оркестратор (bootstrap уже внутри):

```bash
DISABLE_TELEMETRY=1 npx --yes skills@1.7.6 add /Users/vladimir/Programming/Skills/skills --skill orchestrate -a claude-code --copy -y
```

Только исполнитель:

```bash
DISABLE_TELEMETRY=1 npx --yes skills@1.7.6 add /Users/vladimir/Programming/Skills/skills --skill session-worker -a claude-code --copy -y
```

Ниже — общие примеры для авторов: скил `my-skill` должен уже существовать.

Посмотреть список без установки:

```bash
DISABLE_TELEMETRY=1 npx skills@1.7.6 add /Users/vladimir/Programming/Skills/skills --list
```

Установить один скил для Claude Code:

```bash
DISABLE_TELEMETRY=1 npx skills@1.7.6 add /Users/vladimir/Programming/Skills/skills --skill my-skill -a claude-code
```

Укажите свой путь к клону вместо показанного абсолютного пути. Можно передать относительный
путь, например `../Skills/skills`, или путь прямо к `skills/my-skill`. Для другого клиента
используйте `-a codex`, `-a cursor` либо выбор агентов в интерактивном CLI.

По умолчанию установка проектная. `-g` делает её глобальной — не добавляйте его без намерения.
CLI предлагает симлинки либо копирование; `--copy` создаёт независимую копию. После правки
локального исходника не предполагается автоматическое обновление установленной копии:
повторите `skills add` и отдельно проверьте поведение своего клиента.

## Установка из GitHub

Remote ещё не настроен, репозиторий не опубликован. Следующая команда — **форма будущей
установки**, а не действующая ссылка: замените `OWNER`, `REPO` и `main` фактическими значениями.

```bash
DISABLE_TELEMETRY=1 npx skills@1.7.6 add https://github.com/OWNER/REPO/tree/main/skills --skill my-skill -a claude-code
```

Перед публикацией проверьте её из отдельного проекта-потребителя. Наличие совместимого
формата не означает автоматическое включение репозитория в каталог skills.sh.

## Среда авторинга Claude Code

Откройте новую сессию непосредственно в этом каталоге: она загрузит проектные скилы, агентов,
хуки и `.mcp.json`. MCP-сервер может потребовать отдельного подтверждения доверия.

- `/dev` — разработка скила по конкретной задаче; уровень строгости зависит от размера и риска.
- `/memo` — решения и контекст проекта `Skills`; `/memo-bootstrap` — первичная инициализация
  памяти, запускается отдельно, не выполнялась автоматически при переносе.
- `/adapt` — служебная установка набора из `skills/` (файлы в `.agents/skills/`, симлинки в
  `.claude/skills/`). Обновление: установка из `skills/` и `adapt` в режиме обновления.
  Не переписывайте общие скилы под конкретный стек.

memo использует бинарь `/Users/vladimir/.local/bin/memo` и общую БД с изоляцией по scope.
Этот путь относится только к среде авторинга и не должен попадать в распространяемые скилы.
На другой машине нужно настроить свой путь к memo. Reasoner использует локальный
CLIProxyAPI по адресу `http://127.0.0.1:8317/v1`; модель задаётся в `agentmemory.toml`.
Передайте один из ключей `api-keys` конфига CLIProxyAPI через переменную окружения
`CLIPROXY_API_KEY` или локальную `.env` (она исключена из Git). Не записывайте ключ
в TOML или README. При пустом ключе или недоступном прокси память работает без reasoner;
без доступного Ollama предусмотрен FTS5. Доступность сервисов нужно проверять отдельно.
Эта настройка относится к среде авторинга. Публичному `orchestrate` нужен свой настроенный
пользователем MCP memo с подтверждённым scope; авторские пути, CLIProxyAPI и его конфигурация
ему не требуются. `session-worker` без собственного memo требует назначенного независимого
verifier с memo и проверяемым путём получения evidence; иначе v3 блокирует submission.
